Use the existing isolated checkout /workspace/PRISMA-PRIM-Suite. Do not create a Git worktree or another permanent checkout unless the user explicitly requests one. Read AGENTS.md and the Codex Cloud environment section of docs/agents/environment.md; for implementation follow docs/agents/issue-execution.md. This environment is authorized for cloud PostgreSQL and browser development. Keep tracked source, tests, dependency manifests and lockfiles unchanged during setup.

Initialize EVERY command shell:
source /workspace/prisma-cloud-tools/activate-prisma-cloud.sh
cd /workspace/PRISMA-PRIM-Suite
gh --version
pnpm --version
node scripts/agent-doctor.mjs --profile web --readiness-profile cloud

Expected tools: the supplied Node 24, pnpm 11.20.0, GitHub CLI 2.102.0 and the repository's Playwright Chromium. The activation file selects the installed binaries and private writable caches under /workspace/prisma-cloud-tools/cache; pnpm 11 honors pnpm_config_store_dir, not npm_config_store_dir, and XDG_CACHE_HOME keeps GitHub CLI caches off the read-only home. A failing doctor means the environment is not ready: report it and do not patch the doctor during setup. Do not add an inline Node bootstrap or native PostgreSQL lifecycle scripts. Never configure or overwrite GitHub tokens, run an interactive login, replace proxy/CA settings or disable TLS/signature verification.

For another already-authorized checkout, source the same activation file, cd to its real Git root, read its instructions, then run:
bash scripts/agent-pnpm.sh install --frozen-lockfile --prefer-offline
node scripts/agent-doctor.mjs --profile web --readiness-profile cloud
Each checkout has its own node_modules; share only package caches, never symlinked node_modules.

PostgreSQL: run databases only through the managed runner, which creates unique Docker resources and isolated development and _test databases, migrates them, injects safe temporary URLs and removes everything after the command:
node scripts/managed-postgres.mjs -- bash -c 'node scripts/agent-doctor.mjs --profile web-postgres --readiness-profile cloud && pnpm test:preflight:postgres-smoke && pnpm test:preflight:migration'
Preserve registry credentials and use only the Docker socket the activation selects (docker --host=unix:///var/run/docker.sock info). Do not source .env.example inside the runner or override its URLs; no persistent database credentials belong in environment settings.

Verification budget: the host has a four-vCPU quota, so run the full gate with one worker, scoped to the command:
VITEST_MAX_WORKERS=1 node scripts/managed-postgres.mjs -- pnpm verify
Never force two workers globally: Vitest's environment override can defeat --no-file-parallelism. Preserve test and hook deadlines, assertions and GitHub Actions policy. Run heavy checks sequentially.

Browser checks: browser configurations share one preview port. Use the aligned configs the Install script writes; they import the repository configuration and only extend webServer startup to 180 seconds for cold compilation:
pnpm --filter @prisma-prim/web exec playwright test --config /workspace/prisma-cloud-tools/playwright-aligned.config.mjs e2e/production-shell.spec.ts --grep 'renders the production shell'
node scripts/managed-postgres.mjs -- bash -c 'node scripts/agent-doctor.mjs --profile web-postgres --readiness-profile cloud && pnpm --filter @prisma-prim/web exec playwright test --config /workspace/prisma-cloud-tools/playwright-aligned-acceptance.config.mjs e2e/client-registration-refresh.acceptance.spec.ts e2e/operational-foundation.acceptance.spec.ts'
These configs target /workspace/PRISMA-PRIM-Suite; another checkout needs its own external configuration. Do not use configurations that select a system Chromium. This Debian host runs Playwright's fallback Chromium build, so claim browser behaviour only from an actual launch and interaction, never from equivalence with Ubuntu CI.

Cancellation does not reliably stop a command at the execution-tool boundary, and closing the session proves nothing. Before a long workload, record the owning manager PID, command and unique log path. To cancel, validate that PID, command and UID, send SIGTERM only to that manager, then confirm its test descendants stopped and its labelled container, volume, network and temporary directory are gone before starting a replacement; a zombie manager left for the provider to reap is not a running test. Never use broad pkill, Docker prune or daemon restarts.

Networking stays restricted to the domains listed in docs/agents/environment.md. Read a failed GitHub Actions job through its check-run annotations and step summary on api.github.com. Never put log content, signed URLs or credentials into public evidence. Reports go in the pull request or the issue: the advertised /codex/browser output path is read-only.

For frontend development, start the repository web dev command in a persistent session and verify internal requests; do not expose loopback links as user previews. For Clerk or other external services, use only issue-authorized configured credentials, never invented values. GitHub CI remains the authoritative integration gate. A running task keeps the configuration it started with; prove a configuration change in a new task.
