- A changed source, association or native revision between preparation and finalization refuses the stale command. Source parsing happens outside transactions; finalization rechecks its observed scope.
- Two source/review commands on one observed revision serialize; one commit wins and the other gets a stale conflict. Exact same-key retries return one receipt and append no second history event.
- A replaced Company/session/Project/request owner prevents late UI publication and file release. Independent successful writes retain confirmation if a later read fails.
- Hidden and missing sources have indistinguishable refusals; returned results, snippets, derived facts and counts contain only currently authorized evidence.
- Historical runs never restore revoked native rights or substitute a newer/equal-hash Representation. Stale is distinct from unavailable and no detected candidate is distinct from unreadable coverage.
