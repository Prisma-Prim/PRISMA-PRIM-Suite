# Journey map

**Status:** Active ([#1277](https://github.com/Prisma-Prim/PRISMA-PRIM-Suite/issues/1277), access added by [#1341](https://github.com/Prisma-Prim/PRISMA-PRIM-Suite/issues/1341))

This map says what the application shows and how a user reaches it. [Sections](#sections) lists every navigation section of the application shell; [Journeys](#journeys) gives one row per acceptance journey, `apps/web/e2e/<journey>.acceptance.spec.ts`, named as `pnpm verify:journey --list` prints it. `scripts/journey-map.test.mjs` keeps both tables in step with the code. Add or correct the rows in the pull request that adds or changes a spec or a section.

**Find a screen.** Given a screen or a screenshot, find its section below by navigation label or by what it shows, pick a journey that walks it, and follow that journey's Access cell; then replay the journey with the [verify skill](../verify/SKILL.md) to reproduce what the screen shows.

**Reaching a section.** A section shown to the member opens at `/#<section>` or from the primary navigation, behind `Open navigation` at the narrow width. The overview is the home screen at `/`. Prisme is the only frame. An Access cell names the sections a journey enters, in walking order, each followed by the controls it uses there by their English accessible names.

**Widths.** Every journey is walked at both acceptance widths: desktop, 1440 × 900 (`operational-acceptance-desktop`), and narrow, 390 × 844 (`operational-acceptance-narrow`).

**Roles.** The fictional members come from the acceptance global setup; each journey's fixture grants them its Company role bundles. The member shown in the browser is listed first; the others act through the API in the spec, and an audit walks their screens by sending their test identity headers. The first audit that walks a journey corrects its row when the spec shows other roles.
